## Migration on first open: what the plugin does

Found: **it auto-migrates.** `crmRuntime(root)` (used by the plugin on the first `/__crm/*` request and by Jarvis) calls `openCrmStore`, which backs the file up if it still has Leads tables at schema 0 and then runs `migrateCrm` in the `CrmStore` constructor. On a real `crm.sqlite` that would have happened on the first visit to `/crm`.

Changed: `scripts/crm/upgrade-guard.ts` reads the file read-only before anything opens. A file that exists, has Leads tables and is below schema 1 is refused with `CrmNeedsUpgradeError`; the route answers `503 {code:"needs-upgrade"}`, Jarvis says so in one sentence, and the CRM page shows "CRM needs its one-time upgrade" (Leads keeps working). No file is created, migrated or backed up by the hub. A hub with no `crm.sqlite` at all may create one at the current schema. After the owner runs `bun scripts/crm/migrate.ts --db <file> --apply --backup <new file>` the next request opens normally, with no restart (verified on a live synthetic hub).

Proven by `scripts/crm/hub-integration.test.ts` (file hash unchanged, no migration table created, then ready after the owner migration) and on a synthetic hub: 503 before, 200 after.
