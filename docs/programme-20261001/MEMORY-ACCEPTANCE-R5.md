## The memory screen: monotone against the base, six narrow exceptions (final design)

Round 3 had fixed "the password is stored hashed". The creative job's handoff objective was still "withheld" and `4465ff87` failed with `prohibited-content`; their real text was not read. Two independent reviews showed that the first two versions of this round let strings through that the base (`af45e77`) refused. The final `scripts/memory/guard.ts` is the base plus additions that only refuse more, with exactly six allow-conditions, each a tight condition at the place the base refused (not a general exemption):

| # | Shape saved (the base refused it) | Tight condition |
|---|---|---|
| 1 | A Windows drive path in prose, `C:/Users/x/source/repos/mu-creative` | a single drive letter, then a path whose slash is glued to it; `Xero: /jane.admin / pass`, `Notes C:/Users/x/jane.admin / pass` and `C:\Users\x\notes: password hunter2x9` stay refused |
| 2 | A variable NAME with no value after it, `set OPENROUTER_API_KEY in the env`, `webhook secret STRIPE_WEBHOOK_SECRET from env` | a credential-suffixed upper-case name, only after set / export / read / from / in / via / named / called (or as the first word after a weak label), and no value-shaped token after it; `the key is MY_SECRET_KEY` stays refused |
| 3 | A type annotation, `password: str \| None = None`, `type Creds = { user: string, password: string }` | after the type word, only punctuation, types, None / null / undefined, stop words and short lowercase words, on that line and the next; any quoted string or any other token of 6 or more characters refuses (`password: str \| None = "Hunter2x9!"`, `password: string` then `Hunter2x9!` on the next line, `password: any, Hunter2x9!`, `private password: string; // Hunter2x9!` all stay refused) |
| 4 | A run, job, commit or ticket id, `never logged (run 1ff900c)` | in parentheses, straight after a participle (logged, hashed, stored, rotated...), 1 to 6 digits or 6 to 12 hex, never pure digits after a pin, code or password label; `the pin is only ticket 4821`, `the api key is only sha 3a18f6d4b290`, `the password is never logged, it is run 4821` stay refused |
| 5 | A compound noun phrase, `API key rotation page is in settings` | only when the whole tail after the noun is ordinary words and variable names; any other word (a passphrase such as `sunflowerfield`, `correct horse battery staple`) refuses |
| 6 | A glued `?token=abc`, `key=abcdefg` | the value is all lowercase and under 8 characters |

Two URL shapes the owner hits are also saved: `Label: https://host.tld/a/b?x=1#frag` (a well-formed URL token with its slash glued, no user info) and a `login?next=/home` link.

Differential result against the base on both reviewers' corpora (`fixtures/r5-review-corpus.ts`, `r5-review2-corpus.ts`; base verdicts frozen in `fixtures/r5-base-blocked.json`) plus every string literal in `scripts/memory` (3,501 strings, 363 of which the base refused): of the 901 corpus strings the base refused **582**; the head refuses **all but 27 entries, which are 21 distinct allowlisted texts**, each inside one of the shapes above (`guard-r5-review.test.ts`, which also asserts each allowlisted text still saves and that every other base-refused string is refused). The head also refuses 141 strings the base saved (additive). Ordinary strings from the earlier first version that fall outside the six shapes are refused again, as the base refused them (for example `username and password with the password hashed`, `https://login.example.com/login/reset`, `claude:max-2 and codex:openai-1`), and are listed in `guard-r5-false-positives.test.ts` as kept refused.

Additions that only refuse more (all in the tests): credential-named assignments in every form (`FOO_API_KEY=x`, JSON-quoted, `export`, `$env:`, `is` / `to`, newline, `_PASS`, `_PWD`, `_SK`, `_AUTH`, `PGPASSWORD`; a closed `${X}` / `%X%` / `<your-key>` placeholder is skipped but `<Hunter2x9>` is not); a glued value for a weak label at 8 or more characters; "the password is" then a new line; ElevenLabs `sk_` + 40 hex, Retell `key_` + 20 hex, Google `ya29.`, Slack webhook URLs, PGP private key blocks, `Bearer` + 20 mixed, `Authorization: Basic` with a decoded `user:pass`, `curl -u`, `mysql -p`, `sshpass -p`, `docker login -p`, `--password X`, `--token X`, `redis://:pass@host`, `https://TOKEN@github.com/...`, `pass=` / `pass:` with a value, a key split by spaces around hyphens or a line break, and a card number run together with its expiry and CVV (`4111111111111111 12/29 123`).
