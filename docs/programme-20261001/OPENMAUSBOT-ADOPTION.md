| # | Pattern (where) | What it does | Our equivalent | Decision |
|---|---|---|---|---|
| 1 | **Who is driving: the control record** (`computer-control.ts`) | One record per bot: a person `take`s and `release`s; the bot can only *ask* (`requestHelp`) and cannot clear a hold; while held the bot's computer actions are **refused, not queued** ("a queued click would land after the person has moved on"); releasing also settles the bot's pending help request; state is in memory per boot on purpose | `scripts/computers/lease.ts` | **Reuse the idea, all three rules.** Refuse-not-queue is our `Dispatcher.guard`. In-memory-per-boot is our choice too. We **differ**: a person waits for a safe step boundary instead of freezing the agent mid-action; leases **expire** (theirs has no expiry); a fencing epoch kills a stale holder's late command. **Leave out for now:** the agent asking a person to take over (`requestHelp`): worth building later on the same `takeover-requested` event |
| 2 | **A short, renewable ownership fence** (`local-vm-lease.ts`) | A TTL lease over a desktop; runtime activity touches it; a dead provider cannot pin the VM; claim, touch, release are synchronous so lifecycle routes and turn dispatch race safely | `LeaseManager.renew` and lazy expiry | **Reuse the idea.** Same properties (synchronous, TTL, activity renews). Our lease is keyed per device id, theirs per target key |
| 3 | **Seat pool with affinity** (`local-vm-seat-pool.ts`) | Several interchangeable desktops; a conversation prefers its previous seat for 30 minutes | (none: computers are named and explicitly targeted) | **Leave out.** Name-addressed computers match the owner's table. If agents outnumber computers later, a pool with affinity is the model |
| 4 | **Idle timer to suspend** (`local-vm-idle.ts`) | A renewable deadline; busy defers it a full window; suspends the disposable VM | `idleSuspendMs` in the service (off by default) | **Reuse the idea**, implemented, tested |
| 5 | **Per-bot container on your VPS over Docker-over-SSH** (`vps-computer.ts`, `byo-vps.md`) | One hardened container per bot (caps dropped, private namespaces, no host mounts, memory/CPU/pid limits); **no published ports, and a container that publishes one is refused before every attach**; status checks in a fixed order (alias, daemon, image, container, unsafe, desktop) with one fix per message; sleep = stop; remove is the owner's, by hand; everything through an SSH alias so no key is held | `vps-ssh` adapter and `computer-ctl.sh` (sketched); `HostCheck` | **Adapt the ideas, not the code.** We use Unix users and processes, not Docker (no daemon to trust; membership of the docker group is root-equivalent, as their own doc says, and a fresh VPS needs nothing installed beyond the desktop packages). Kept: SSH alias only, `BatchMode`, no key or password in our code, no public port, destroy is explicit, ordered honest status messages. **Borrow next:** refuse to attach to a computer that listens on a non-loopback port (check inside `probe`), and per-computer Unix users or containers for real isolation |
| 6 | **Loopback-only noVNC, random viewer path, SSH tunnel; relay through a local service** (`desktop-viewer.cjs`, `docs/desktop-companion.md`) | The VNC/noVNC server binds 127.0.0.1 (random port); the tunnel closes with the viewer; HTTPS required for cloud viewers with one HTTP exception for loopback; closing the viewer hands control back | `/__computers/<name>/vnc` and `RfbGate` | **Adapt the idea.** We terminate the viewer on the hub's authenticated WebSocket, with no port at all (stdio tunnel: `wsl.exe` /dev/tcp, `ssh -W`), and **filter the RFB stream** so a viewer without the lease cannot send a key or click. Theirs gates control by a per-device permission defaulting off; ours by the lease and the confirmed-person rule, with both founders allowed to view by the owner's decision |

| 8 | **Default-deny companion API with a route allow-list, response scrubbing, bearer injected by a loopback relay** (`docs/desktop-companion.md`) | The client never holds a token in the page; transports limited to managed HTTPS or `.ts.net`; raw IPs, LAN names, URL credentials and paths rejected | `scripts/computers/bridge.ts` (the allow-list part); the token is only ever used on `/__devices/companion/*` | **Adapt.** Closest analogue is our bridge: one interface, seven routes, headers stripped, 404 elsewhere. We **deliberately relax** their "no raw IPs" rule for the bridge address because WSL's NAT gives only a private address; the allow-list, the single interface and the header rewrite are what make that safe |
| 9 | **An owned host, never an unowned one** (`cua.mjs`, `cua-windows-isolation.test.mjs`) | Start only the driver this app owns; a failed start is reported as unavailable, never a fallback to a foreign daemon or pipe; the test mocks `child_process` and `net` to **throw** ("unowned launch", "foreign pipe probed") so any fallback fails the test | our cross-owner tests; `computer-ctl.sh` pid files hold start time | **Reuse the test technique.** Our cross-owner tests assert `dispatcher.recent()` is empty (nothing queued anywhere), the same "fail if it tries" shape. Our script never adopts a process it did not start: a pid file stores the start time so a recycled pid is not ours |
| 10 | **Descriptor validation with file identity** (`local-computer.ts`) | Exact key sets, versions, a generation id, and the driver binary's inode/size/mtime checked again by the server, not just by Electron | none yet | **Leave out; note.** The companion bundle is a single file we copy; pinning its sha256 in the script and checking it before start is a cheap follow-up |
| 11 | **Pure capability detection with reason codes** (`capabilities.cjs`) | `x11`, `wayland`, `headless`, each with `reasonCode` and a message; nothing unsupported is silently attempted | `HostCheck` (`missing`, `notes`, `installCommand`); `desktop: false` | **Reuse the idea.** A computer on a host without a desktop says "headless" and lists the exact fix instead of pretending |
| 12 | **Waiting words for a busy computer** (`computer-wait.ts`) | One phrasing everywhere ("Waiting for its turn on this computer: bot is running thread"): a queue position, not an error; gives up after 30 minutes naming the holder | the 409 "agent X is using research; one controller at a time, so nothing ran" | **Reuse the wording discipline.** We refuse rather than queue (an agent starts a job on purpose); a queue is a later feature. Agent C should use one phrase for it on every surface |
| 13 | **Fan-in event bus, stamped per instance, redacted, teed to an NDJSON log** (`harness/bus.ts`) | Every driver's events merge into one bus; an adapter may only emit its own kind (cross-driver events dropped); the canonical log scrubs credential-shaped text; a failed log write raises one warning and the next event records the gap | the job store's events (`jobs.sqlite`), `maskJobText`, `Dispatcher.complete` (only the device a command went to may report it) | **Reuse the invariants, leave out the bus.** We already have one job log per job and a one-way rule that a device may only report its own commands. | 14 | **Provider registry with shadow snapshots** (`harness/registry.ts`) | An unknown driver or config that does not decode becomes an *unavailable shadow snapshot*, not a startup failure, so settings stay forward and backward compatible | the `adapters` map; a computer whose host is not configured answers "the host isn't configured" while the list still works | **Reuse the idea**, done |

## 3. What this changed in our design

* Kept refuse-not-queue for a held computer; added a **fencing epoch** and a **safe-boundary pause** (better than freezing an agent mid-action).
* The viewer has **no port at all** and is filtered at the byte level by the lease: stronger than a per-device flag.
* The bridge exists because WSL is not a VM; it follows their allow-list-at-the-edge shape.
* Idle suspend, honest host reports, in-memory frames and the "fail if it falls back" test shape come from them.
* Left for later, in this order: the agent's own `requestHelp`; refuse-to-attach on an unexpected listening port; bundle hash pinning; a seat pool.
