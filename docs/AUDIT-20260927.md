**A-H2. The control deny-list (`controlPolicyPermits`) misses banking, trading and secret-file tasks, and those tasks classify as low risk.**
- **Location.** `scripts/jarvis-execution/runtime.ts:24-26`. The tiers come from `src/lib/control-risk.ts`.
- **Evidence.** I ran a synthetic probe. Each line shows what the policy returned, then the risk tier:
  - `Open the NAB app and send John $500` → PERMIT, external-effect
  - `Open CommBank and pay Jo 200 dollars` → PERMIT
  - `Use PayID to send 300 to …` → PERMIT
  - `Log into Westpac and set up a BPAY to Origin` → PERMIT
  - `Sell my BHP shares on CommSec` → PERMIT
  - `Buy 0.1 bitcoin on CoinSpot` → PERMIT
  - `open ~/.config/agentic-os.env in notepad` → PERMIT, **local-reversible**, so no spoken yes is needed
  - `read the TypeSafe key from config.yaml` → PERMIT, **read-only**
- **Failure scenario.** Once the Hermes retention gate is lifted, one spoken "yes" is enough to approve a bank transfer or a share or crypto trade. The owner's hard rule is "never execute a trade or transfer". Reading the secrets file needs no confirmation at all.
- **Current exposure.** Not reachable today, because of the 503 refusal. This is a **release blocker for enabling control**.
- **Fix.**
  - Replace the regex with an allowlist of permitted verbs and apps, plus a denylist that covers: `send|pay|transfer|PayID|BPAY|Osko|buy|sell|trade|order|withdraw`; bank, broker and exchange names (NAB, CommBank/CBA, Westpac, ANZ, CommSec, Stake, IBKR, CoinSpot, Binance, Swyftx); and any path or file containing `.env`, `agentic-os.env`, `config.yaml`, `credentials`, `token`, `key`, `secret`.
  - Classify any read of a secret-bearing path as refused, not read-only.
  - Add these probe strings as permanent tests.

**A-M2. Two paths still reach NAB or finance data without legacy admission.**

**A-M3. The server-side control "approval" is a rubber stamp minted by the client.**
- **Location.** `src/lib/jarvis-control.ts` (uncommitted), in `dispatchHermesTask`: it sends `confirmation: "yes"` as a literal. `ControlDispatchGate.issue` (`scripts/jarvis-execution/server-approval.ts:67-77`) accepts any `isAffirmative` string from any holder of the page token.
- **Scenario.** Any same-origin script, or any tab of the app, can mint a server grant for any task. The grant proves only that the task text matches, **not** that a person said yes.
- **Current exposure.** This is within the documented trust boundary and is unreachable while the 503 is in place.
- **Fix.** Do not describe this as independent human approval. Before control is enabled, bind issuance to the voice pipeline's own confirmation event, and keep the server-side record of it.

**A-M4. A normal child exit never checks for orphaned descendants.**
- **Location.** `runtime.ts:205-215`. `verified({ok: code===0})` fires on `close` with no process-tree accounting. Quarantine is triggered only by an unacknowledged *stop*.
- **Scenario.** Hermes spawns a detached helper (a browser, or a PowerShell script) and exits 0. The job settles, admission stays open, and the helper keeps acting.
- **What already holds.** The journal records such a job as `unverified`, not succeeded, which is correct.
- **Fix.** On close, capture the tree the same way `quarantine()` does and quarantine if any descendant survives.

**A-M5. The combined uncommitted diff mixes six independent tracks, and a partial rename is already staged.**
- **Detail.** `git diff --cached` holds three staged renames: `src/routes/{dashboard,setup,agents.hermes}.tsx` → `src/routes/-pages/*`. The new thin route files at the original paths are **untracked**.
- **Scenario.** A plain `git commit` of the current index deletes the `/dashboard`, `/setup` and `/agents/hermes` routes, and `src/routes/codegraph.tsx`'s import `./-pages/hermes` resolves only by accident.
